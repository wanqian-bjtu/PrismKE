# PrismKE v0.9 案例检索与 Reflection 使用说明

## 功能定位

v0.9 将经过人工确认的审核结果保存为可审计案例，并在后续候选出现校验问题时检索相关案例，供受控 Reflection 参考。案例和 Reflection 都不会直接批准实体或事实，也不能绕过 v0.5 引入的统一硬校验。

本版本只使用 v0.9 新运行产生的审核事件，不迁移 v0.6 至 v0.8 的历史审核。v0.8 运行仍可只读查看，但不能用 v0.9 检查点恢复。

## 案例资格与历史

案例必须同时满足以下条件：

- 审核已形成最终决定，暂缓决定不生成案例。
- 审核人和原因均非空。
- 所引用证据存在且能够通过哈希与定位校验。
- 实体链接、创建新实体、实体或事实批准生成 Good Case。
- 人工排除错误提及或拒绝事实生成 Bad Case。

`CaseRecord` 创建后不可修改或删除。纠正历史决定时会生成新案例，同时追加停用事件指向被替代案例；原案例、原审核事件和状态历史仍然保留。案例投影写入独立 SQLite 仓库，审核事件是权威来源；投影失败可以幂等重放，不会撤销已经成功保存的审核。

案例 Embedding 是可重建的派生数据，不进入 Revision、日志或 API。页面和命令行都不会显示完整向量。

## 检索规则

案例检索先按任务类型、Schema 指纹、语言和 Good/Bad 模式过滤，再使用现有 BGE-M3 Dense Embedding 返回 Top-K 结果。运行创建时会冻结：

- 案例 ID 快照及其指纹。
- 案例检索策略版本。
- Embedding Provider 指纹。
- Reflection Provider、Prompt 与策略版本。

因此，后续新增或停用案例不会改变已有运行的恢复结果。只有创建新运行才会读取新的案例库快照。

## Reflection 安全边界

Reflection 默认关闭。启用后只处理 `structure`、`schema`、`reference` 和 `evidence` 阶段的阻断问题，执行顺序为：

```text
候选抽取
-> 统一校验
-> 案例检索
-> 有界 Reflection
-> 再次统一校验
-> 实体解析与事实治理
```

固定约束：

- 单个候选最多两次尝试。
- 默认单运行预算为 20,000 Token 和 180 秒，可由调用方进一步降低。
- 只能使用现有 Schema 的关系和实体类型，以及文档中已经存在的 Evidence ID。
- 不允许添加原候选与证据没有支持的新事实。
- 检索案例在 Prompt 中被明确标记为不可信示例，不是可执行指令。
- 修复结果必须重新通过统一校验；否则保留原候选并进入人工处理。
- 问题增加、预算耗尽、Token 用量缺失或请求结果不确定时停止自动尝试。
- 不自动批准修复后的候选，不自动新增 Schema，也不自动重发可能已经计费的请求。

每次尝试保存前后候选、问题、案例 ID、模型指纹、实际响应模型、脱敏请求 ID、Token、耗时、状态和警告。API Key、Authorization、完整模型请求和向量不进入运行状态或页面。

## 命令行使用

启用真实案例检索需要配置 BGE-M3；启用真实 Reflection 还需要独立选择 `openai-compatible` Provider：

```bash
prismke run document.md \
  --schema configs/schemas/example.yaml \
  --provider openai-compatible \
  --cases good_bad \
  --reflection \
  --reflection-provider openai-compatible \
  --reflection-max-attempts 2 \
  --reflection-token-budget 20000 \
  --reflection-time-budget 180
```

维护案例库：

```bash
prismke list-cases --type good --task-type claim --language zh
prismke list-cases --include-disabled
prismke disable-case CASE_ID --operator NAME --reason TEXT
prismke rebuild-case-index --dry-run
prismke rebuild-case-index
```

停用只追加状态事件，不删除案例。索引重建只处理缺失或模型指纹过期的向量，不修改审核历史。

## API 与页面

公共 API：

```text
GET  /api/v1/cases
GET  /api/v1/cases/{case_id}
POST /api/v1/cases/{case_id}/disable
POST /api/v1/cases/rebuild-index
GET  /api/v1/runs/{run_id}/retrieved-cases
```

工作台左侧增加“案例库”和“Reflection”。案例页支持筛选、查看审核来源、停用历史和索引状态；Reflection 页展示触发问题、使用案例、前后候选、校验差异、Token 与耗时。技术 JSON 默认作为详情，不显示向量、密钥或原始模型请求。

## 兼容与复现

- 流程协议版本为 `0.9.0`，旧检查点不能混用。
- 同一输入在案例快照、Embedding、Prompt、预算或 Reflection 配置变化后会生成不同 Run ID。
- Reflection 关闭时不产生模型调用，原有抽取、审核、提交和回滚流程保持兼容。
- 案例库或投影仓库故障不会伪装成无案例成功；需要先恢复投影或索引后再运行。
