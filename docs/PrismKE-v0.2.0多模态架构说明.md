# PrismKE v0.2.0 多模态架构说明

## 版本目标

v0.2.0 将 PrismKE 的输入从纯文本扩展到文本、OCR 与图片，并保持 Claim 级证据、风险审核、原子写图和检查点恢复能力。它不把图片本身当成领域实体，而是将图片保存为 `MediaAsset`，将图中可定位的观察保存为 `VisualObservation`，再把真实对象映射为 `CanonicalEntity`。

## 处理流程

```text
文件输入
  -> 文档与图片解析
  -> 扫描页/图片 OCR
  -> 内容寻址证据持久化
  -> Schema 加载
       |-> 文本 Claim 抽取 ----------------|
       |-> 视觉 Observation 与 Claim 抽取 -|-> 跨模态对齐
  -> 实体解析与 Claim 规范化
  -> 风险审核
  -> 原子 GraphCommit
```

文本与视觉抽取是 LangGraph 中的两个并行分支，各自保存检查点；一个分支失败不会丢失另一个分支已经完成的结果。文本模型、OCR 和 VLM 使用三个独立 Provider。只有用户显式选择对应 Provider 时才会调用，配置缺失会直接报错。

## 证据模型

- 文本证据保存字符范围或 PDF 页面 bbox。
- OCR 证据保存媒体资产、像素 bbox、识别模型和置信度。
- VLM 优先返回归一化区域 bbox；不能定位时使用整图证据并标记 `localization_level=asset`。
- 每个媒体二进制按 SHA-256 保存一次，同一图片在不同文档位置仍保留不同的出现记录。
- 视觉独有且只有整图证据的 Claim 必须人工审核。

## 跨模态对齐

对齐层使用 Schema 关系别名、规范化主语、对象和页面上下文形成候选签名，不额外调用模型。图文表达同一事实时合并证据，并在最高原始置信度上增加 `0.05`，上限为 `0.99`。OCR 与 PDF 原生文本不被视为两个独立模态支持，避免重复计分。

对齐结果分为 `support`、`conflict`、`related` 和 `independent`。同一主语和关系出现不同对象时只记录对齐冲突；共享主语但表达不同关系时记录为相关。最终是否构成知识冲突仍由 Schema 的功能性、最大基数和有效时间规则决定。

## 兼容边界

- 原来的 `--provider` 参数继续表示文本 LLM。
- 默认关闭 OCR 和 VLM，因此 v0.1.1 文本命令保持可用。
- v0.1.1 的运行记录可以查看，但不能使用 v0.2.0 工作流恢复。
- 本版仍使用 JSON GraphStore；Neo4j、Web UI、本地 VLM 和持续学习属于后续版本。
