# v0.5 统一校验与迁移说明

稳定软件版本为 `0.5.0`，流程协议为 `0.5.0`，校验策略为 `validation-v1`。

## 处理规则

Provider JSON 解析成功后逐项检查结构，保留合法候选与非法候选的白名单摘要。完整 JSON 经过一次修复仍失败、网络或鉴权失败，仍属于节点失败，不返回伪装成功的空结果。

实体解析前检查类型、关系、证据和视觉观察引用，问题候选不参与实体解析。规范化时进一步检查规范实体映射及 domain/range。正常候选继续处理；未处理的阻断问题使提交暂停。

未知关系在严格、宽松模式下均阻断，不自动修改 Schema，不交换主客体猜测修复。违规候选仅允许排除，普通事实批准不能将它转为正式 Claim。原候选、问题与排除审计保留，排除不等于纠正候选。

校验模型位于 `prismke.domain.validation`；规则位于 `prismke.governance.validation`。软件版本、流程协议和策略指纹分别记录，新运行不会复用 v0.4 检查点。

## 操作

```bash
prismke validate-run RUN_ID
```

只读复核，不更新运行文件、审核状态或图谱；有开放阻断问题时退出码为 1。

API 使用现有认证机制：

```text
GET  /api/v1/runs/{run_id}/validation
POST /api/v1/runs/{run_id}/validation-issues/{issue_id}/exclude
```

排除请求正文：`{"reviewer":"审核人","comment":"原因"}`。审核人不能为空；已处理、过期、版本不兼容或正在被修改的任务返回 409。

页面“校验问题”选择运行，按阶段、代码、状态筛选；选中问题查看候选摘要与证据。填写审核人及意见，确认排除影响后提交。排除后刷新审核页面并继续，正常事实仍按原流程独立审核。隔离工作区写图仍需勾选并确认提交。

## 问题代码

| 代码 | 含义 |
|---|---|
| INVALID_CANDIDATE_STRUCTURE | 单项候选字段、置信度或证据列表不合法 |
| INVALID_OBSERVATION_STRUCTURE | 视觉观察结构、置信度或 bbox 不合法 |
| UNKNOWN_ENTITY_TYPE | Schema 未声明实体类型 |
| UNKNOWN_RELATION | Schema 未声明关系，宽松模式也不能写入 |
| SCHEMA_DOMAIN_RANGE | 主客体类型与关系方向不匹配 |
| MISSING_ENTITY_REFERENCE | 提及或 Claim 未引用有效规范实体 |
| MISSING_CONFLICT_MEMBER | 冲突集合引用未知事实 |
| UNKNOWN_OBSERVATION / UNKNOWN_MEDIA_ASSET | 视觉观察或图片资产引用不存在 |
| UNKNOWN_EVIDENCE / MISSING_EVIDENCE | 证据引用未知或文件不存在 |
| CORRUPT_EVIDENCE / EVIDENCE_REF_MISMATCH | 文件被篡改或运行证据与存储不一致 |
| INVALID_EVIDENCE_LOCATION | 字符范围、页码、bbox、坐标系或画布不合法 |
| MISSING_SCHEMA_CONTEXT | 活动事实缺少可复用 Schema 来源 |
| INCOMPLETE_PIPELINE | 节点失败，运行未完成，不能排除为候选错误 |

文件或数据库不可访问属于运行失败，不应通过排除候选掩盖。合法证据和 bbox 只证明完整性与定位约束，不能证明事实语义正确。

## 存储与旧数据

新 GraphCommit 提供 CommitValidationContext：Schema 规范内容哈希、快照及 Claim 到 Schema 的映射，图片证据同时记录文档资产 ID。来源写入 Revision，事务指纹覆盖实际提交内容。同 Revision ID 不同内容会报错。

JSON 在文件锁内、Neo4j 在 managed transaction 内检查父版本与合并后引用状态，并复核原始证据。预览后证据损坏仍拒绝提交。实体类型或 active 状态变化时也检查受到影响的活动 Claim。校验失败不写半成品。

合并、拆分与回滚使用历史记录中的 Schema，不能按现有名称猜测补齐。只关闭旧 Claim 不要求重新解释旧事实；新增或恢复活动 Claim 缺少上下文则拒绝。迁移 dry-run 显示 blocked_claim_ids，实际迁移在发现缺失来源时阻断；它不会自动修补旧事实。

v0.4 运行和图谱仍可只读查看。需要接续已有审核时，用 v0.4.1 发布代码及原流程环境，不调用模型，不导入 v0.5。服务器保留发布代码副本 `runtime/releases/v0.4.1`。

旧审核工作台的 `8001` 服务已固定到发布副本，运行目录仍为原隔离工作区。重启参考命令如下，不要在 `dev/v0.5` 下直接恢复旧运行：
