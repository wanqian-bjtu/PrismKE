# v0.7 问题记录

日期：2026-09-17。本轮不扩展业务功能或修补全部界面问题。

| 项目 | 位置与复现 | 影响 | 状态/后续处理 |
| --- | --- | --- | --- |
| JSON 信息密集 | web/execution.py 的执行状态、已有审核提交预览 | 移动端需内部滚动，状态阅读成本高 | 保留；后续改为紧凑字段与详细信息折叠，不改变后台语义 |
| 并行节点显示 | workflow/execution.py RunControl.node；文本请求等待时视觉分支可最后更新节点 | 单一节点不能展示两条分支同时在途 | 保留；事件完整，后续增加分支进度列表 |
| 业务与执行状态不同 | 取消后 WorkflowState 可仍为 running，execution 为 cancelled | 用户可能混淆；服务端按钮使用执行状态 | 说明已补，后续优化为中文状态摘要 |
| 其他页标签刷新滞后 | web/review.py 等既有页在后台状态改变后需刷新 | 跨页信息不总是同步 | 保留；本轮执行页每两秒刷新，未扩大修改其他页 |
| 未知请求缺少人工核对入口 | persistence/execution.py requests；发送后超时或无 usage | 安全阻断后不能在界面自行解锁 | 明确边界；后续需有可审计的账单核对协议，禁止直接清库重发 |
| AnyIO 弃用警告 | Starlette TestClient 导入 BlockingPortal | 测试提示未来依赖兼容变更，无当前行为失败 | 保留；后续依赖升级时验证 |

本轮修复了异步恢复测试的提前读取、重复公开执行入口竞争运行锁、图提交成功后投影异常误报失败，以及排队阶段取消后无检查点不能恢复的路径，并有回归测试。以上保留项不默认标记关闭。

多数据库一致性仍通过持久记录、投影恢复和图 Revision 核对实现，未宣称 SQLite/检查点/JSON/Neo4j 之间的原子事务。
