# PrismKE v0.8-v0.9 整体完善计划

日期：2026-09-21。基线版本：v0.7.0（9165713）。

## 当前状态

PrismKE 已具备多模态文档解析、OCR、文本与视觉抽取、实体治理、统一校验、人工审核、证据追溯、JSON/Neo4j 图存储、补偿回滚和持久化任务管理。AutoDL 实例启动后仍需手动执行 `bash scripts/prismke_autodl.sh start`；本次检查中代码与 GitHub 同步，Neo4j、Web 和健康接口均可正常恢复。

当前 Gradio 页面以顶部标签组织功能，入口较多、JSON 展示密集、执行分支进度不清晰。v0.8 借鉴 OneKE 的信息架构，改为左侧导航与配置、右侧主工作区；不复制 OneKE 的 Streamlit 实现，也不把服务器已有密钥回显到浏览器。

## v0.8.0：研究工作台与运行治理

- 使用 Gradio 6 原生 Sidebar 建立总览、新建构建、执行任务、实体审核、事实审核、校验问题、审核纠正、证据、图谱、实体治理、版本和系统状态导航。
- 侧栏集中展示当前运行、业务/执行状态、待审核数量及非敏感配置。Provider、模型别名和非敏感连接项可直接修改；API Key、Neo4j 密码等仅显示是否已配置，不在页面显示、编辑或清除，仍由服务器 `.env` 或安全后端管理。
- 右侧页面以摘要、表格、时间线和证据预览为主；完整 JSON 放入默认折叠的技术详情。移动端侧栏折叠，表格只在自身容器内滚动。
- 增加工作区摘要和文本、视觉、OCR、提交分支进度。业务状态与执行状态分别展示，按钮始终使用服务端允许动作。
- 增加未知请求核对：确认未发送或未计费后才允许重试；可能已计费但响应丢失时继续阻断。核对事件保存操作者、原因和执行版本，不允许清库绕过。
- 不修改抽取算法和实体阈值，不调用百炼，不直接替换生产服务。验收后再决定是否发布 v0.8.0。

## v0.9.0：案例检索与受控 Reflection

- 从具有审核人、原因及完整证据的人工决定生成不可变 Good/Bad Case，使用 BGE-M3 按任务、Schema 和语言召回。
- 案例只作为 Prompt 上下文，不自动批准候选、不自动改变 Schema；运行记录使用了哪些案例、分数及位置。
- Reflection 仅由明确校验问题触发，默认关闭。每个候选最多两次，并设置运行级 Token 和时间预算。
- 修复前后候选、问题、模型、Prompt、Token 和状态全部保留；Reflection 不能绕过硬校验，失败后转人工审核。
- 使用独立开发集与评测集比较无案例、Good Case、Good/Bad Case，以及 0/1/2 次 Reflection；报告修复率、错误改写率、审核率、Token、延迟和证据保持率。

## 暂缓范围

表格/图表专用语义解析、本地 VLM、OpenSPG 适配器、多租户和分布式任务队列不进入 v0.8-v0.9。README 中“向量召回尚未实现”的历史表述需修正；BGE-M3 和 Neo4j Vector Index 已在 v0.4 实现。

## 验收与发布

每个版本均运行 Ruff、Mypy、完整 pytest、隔离 Neo4j 和桌面/平板/移动浏览器测试。运行产物、密钥、原始材料和模型不进入 Git。开发在服务器测试后推送 GitHub，本地快进同步；生产服务升级、main 合并和版本标签均单独确认。
