# v0.6 审核纠正与兼容说明

本说明对应 v0.6.0 发布版本（软件与流程协议均为 0.6.0）。发布未替换生产服务，旧真实审核工作台继续使用冻结的 v0.4.1。开发期记录见隔离验收报告。

## 审核动作

| 对象 | 动作 | 影响 |
|---|---|---|
| 实体提及 | 链接候选 | 链接列表中的现有实体，仍受类型与 Schema 硬校验 |
| 实体提及 | 创建新实体 | 采用原运行保留的实体草稿，不改写实体名称 |
| 实体提及 | 排除错误提及（reject） | 派生候选排除关联事实，原始候选和决定历史保留 |
| 实体提及/事实 | 暂缓判断（defer） | 必须填写原因，任务保持 pending 并继续阻断 |
| 事实 | 批准/拒绝 | 只处理当前事实，不默认替冲突对方决定 |

所有新审核必须填写审核人。排除、暂缓和纠正还必须填写非空原因。已完成任务不能由普通审核接口覆盖；最终决定的改变走纠正提案。页面提交任务所加载的版本，过期版本返回 409。

`reject` 始终表示排除，不表示“只拒绝当前身份候选”。身份不确定时选择暂缓，已确认是其他对象时选择链接或新建。

## 权威记录与恢复

运行目录的 `reviews.sqlite` 保存原始候选、不可变 ReviewEvent、任务版本、纠正提案和投影 outbox。一次审核的事件、版本和待投影状态在同一 SQLite 事务内保存。检查点、运行摘要、图补偿和追加审计日志是后续投影；它们不属于同一数据库事务。

若投影失败，页面/API 显示“同步待恢复”，禁用继续和写图。服务器重新启动会重放 pending outbox；也可在原运行执行 resume 触发恢复。恢复只投影已保存决定，不替用户重新审核，不重新解析、OCR 或抽取。重复 request_id 返回已有结果；同编号不同决定被拒绝。

已成功写图但检查点/日志投影失败时，重放使用相同 Revision 与内容指纹，避免重复补偿。若其间发生其他图版本或资源变化，保留待恢复记录并明确失败，不能自动覆盖新状态。

## 纠正操作

1. 在“审核历史与纠正”选择运行、历史任务和当前最终决定事件。
2. 选择替代动作/候选，填写审核人和原因，生成预览。
3. 检查受影响事实、证据、当前版本和阻断原因，勾选确认后应用。
4. 未写图：从不可变候选重算受影响派生结果；失效事实决定保留历史，正常事实仍需审核。
5. 已写图的身份改变：先重新审核受影响的新事实，再继续生成提交摘要，最后明确确认补偿写图。
6. 已写图的事实拒绝关闭事务时间；恢复使用当前事务时间和完整前后快照。旧事件、旧事实 ID、历史 Revision 不物理删除。

初次“确认应用纠正”只记录替代决定并准备后续处理，不自动提交图谱。已写图纠正的最后确认将补偿投影登记到 outbox，再执行图事务。JSON 使用文件锁；Neo4j 使用 managed transaction，在原子边界内检查父版本、资源指纹、快照、Schema 与证据。

补偿只更新预览涉及的实体/事实，不沿用普通追加的证据并集或最高置信度策略。若资源受到其他运行或文档支持，或缺少运行来源，首版拒绝自动纠正。不会自动合并/拆分实体。回滚保留历史并拒绝覆盖已变更资源；图版本回滚不会删除审核历史。

## 接口

```text
GET  /api/v1/runs/{run_id}/review-events
POST /api/v1/runs/{run_id}/review-corrections
GET  /api/v1/review-corrections/{correction_id}
POST /api/v1/review-corrections/{correction_id}/apply
```

提案提交 source_event_id、替代 action、可选 selected_entity_id、expected_version、reviewer、reason 和 request_id。应用提交 `{"confirm": true}`。普通审核兼容原入口，增加 defer、expected_version 和 request_id；页面必须携带已加载的任务版本。

## 兼容与限制

- v0.4/v0.5 运行和图历史可查看，不用 v0.6 恢复或纠正。旧工作台通过原发布代码接续；不猜测补齐历史。
- 导入 v0.6 隔离审核运行必须保留候选归档与已投影审核账本，校验任务版本一致；源有 pending 投影则拒绝导入。
- 校验问题排除没有撤销放行入口；新关系、修改 Schema 和合并/拆分历史纠正不在本轮范围。
- 纠正和隔离接续使用 tail-only 图，不访问抽取 Provider，也不编码新向量；新实体的派生向量可由显式 rebuild-entity-index 重建。普通运行审核后继续保留原索引写入行为。
- 页面当前仍有较多 JSON 细节，运行选择器标签需手动刷新；体验改进记录在问题清单。
- dev/v0.6 不应通过统一启动脚本替换现有生产工作台。测试必须指定新的 runtime、端口和隔离数据库。
- 本轮不调用百炼，不下载模型，不调整阈值，不改真实审核决定；v0.6 发布需另行确认。
