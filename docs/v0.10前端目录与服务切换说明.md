# v0.10 前端目录与服务启动

`dev/v0.10` 是开发版。`frontend/` 保存 Gradio 页面，`src/prismke/api/`
保留 FastAPI 接口；`prismke serve` 将页面挂载到 `/ui/`。没有迁移 Streamlit。
`scripts/start_web.sh` 只启动前台 Web，`scripts/start_neo4j.sh` 只启动
Neo4j；`scripts/prismke.sh start` 在 tmux 中后台管理两者。脚本按自身位置定位
项目，不包含 AutoDL 或 Conda 的绝对路径。适用于配置了 Bash、Java、tmux、
curl、flock 和项目 `.venv` 的 Linux/WSL 主机；Neo4j 可用
`bash scripts/install_neo4j.sh` 安装到项目运行目录。旧 `_autodl.sh` 文件仅是
兼容转发，不包含另一套服务逻辑。

不进入 Git 或页面。模型缓存仍可从原项目目录复用。

## 启动与访问

在任意工作目录执行（先将路径改为实际检出的项目目录）：

```bash
PROJECT=/path/to/PrismKE
bash "$PROJECT/scripts/prismke.sh" start
bash "$PROJECT/scripts/prismke.sh" status
```

直接前台启动时先执行 `bash "$PROJECT/scripts/start_neo4j.sh"`，再执行
`bash "$PROJECT/scripts/start_web.sh"`；后者占用当前终端，`Ctrl+C` 停止。
每次主机开机后需要重新执行后台 `start`，没有配置自启动。`stop` 先关闭 Web
再关闭 Neo4j。默认运行目录保持 `runtime/services/v010/`，以便当前服务下次
启动继续使用同一图谱；其它部署可设置 `PRISMKE_RUNTIME_DIR`、
`PRISMKE_NEO4J_HOME`、`PRISMKE_API_PORT` 等环境变量。运行配置中的密钥
仍只放在项目 `.env`，不能写进启动命令。

Windows PowerShell 本地转发（保持窗口开启）：

```powershell
ssh -N -p 41051 -L 127.0.0.1:18000:127.0.0.1:8000 `
  -L 127.0.0.1:17474:127.0.0.1:7474 `
  -L 127.0.0.1:17687:127.0.0.1:7687 root@connect.westc.seetacloud.com
```

工作台为 `http://127.0.0.1:18000/ui/`；Neo4j Browser 为
`http://127.0.0.1:17474/`，其 Bolt 地址填写 `bolt://127.0.0.1:17687`。
SSH 转发断开不会停止服务器服务。不要将 8000、7474 或 7687 开放至公网。

## 从 v0.9.2 切换及回退

切换前检查 v0.9.2 的执行仓库没有正在运行、排队或未结算的请求；记录最新
Revision。维护窗口内先有序停止旧 Web/Neo4j，制作最新 Neo4j dump 和应用
状态备份，生成 SHA-256 清单并验证归档，然后才启动 v0.10。新图谱为空，
旧事实不会出现在新页面。切换失败时停止 v0.10，再用原 v0.9.2 代码、
配置和数据恢复；新库如已写入，先独立备份，绝不覆盖旧库。

旧生产实例的命令必须显式携带原目录配置，不能在旧目录或本目录使用
未核对的默认值执行 `stop`/`start`。v0.10 的 Git 部署不代表发布正式版本。
