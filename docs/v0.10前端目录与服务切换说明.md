# v0.10 前端目录与 AutoDL 服务

`dev/v0.10` 是开发版。`frontend/` 保存 Gradio 页面，`src/prismke/api/`
保留 FastAPI 接口；`prismke serve` 将页面挂载到 `/ui/`。没有迁移 Streamlit。
`scripts/start_web.sh` 只启动前台 Web，`scripts/start_neo4j.sh` 只启动
Neo4j；`scripts/prismke_autodl.sh start` 在 tmux 中后台管理两者。

## Neo4j 位置

| 内容 | 服务器路径 |
|---|---|
| 安装包 | `/root/autodl-tmp/PrismKE/runtime/neo4j/neo4j-community-5.26.30-unix.tar.gz` |
| 程序 | `/root/autodl-tmp/PrismKE/runtime/neo4j/current`，指向 `neo4j-community-5.26.30/` |
| 旧 v0.9.2 配置 | `/root/autodl-tmp/PrismKE-v092-prod/runtime/canary-v092/production/neo4j/conf/neo4j.conf` |
| 旧 v0.9.2 数据 | `/root/autodl-tmp/PrismKE-v092-prod/runtime/canary-v092/production/neo4j/data/` |
| v0.10 新配置 | `/root/autodl-tmp/PrismKE/runtime/services/v010/neo4j/conf/neo4j.conf` |
| v0.10 新数据 | `/root/autodl-tmp/PrismKE/runtime/services/v010/neo4j/data/` |

旧 `/root/autodl-tmp/PrismKE/runtime/neo4j/data/` 也保留，不是 v0.10 的数据源。
新配置只监听回环地址，独立运行目录保存证据、检查点、审核与日志。
启动脚本不下载 Neo4j 或覆盖现有图谱。`.env` 中的 Key 和密码只保留在服务器，
不进入 Git 或页面。模型缓存仍可从原项目目录复用。

## 启动与访问

在服务器的项目目录执行：

```bash
cd /root/autodl-tmp/PrismKE
bash scripts/prismke_autodl.sh start
bash scripts/prismke_autodl.sh status
```

直接前台启动时先执行 `bash scripts/start_neo4j.sh`，再执行
`bash scripts/start_web.sh`；后者占用当前终端，`Ctrl+C` 停止。
上述脚本也可从其他目录使用绝对路径调用。每次 AutoDL 开机后需要重新执行
后台 `start`，没有配置自启动。`stop` 先关闭 Web 再关闭 Neo4j。

Windows PowerShell 本地转发（保持窗口开启）：

```powershell
ssh -N -p 41051 -L 127.0.0.1:18000:127.0.0.1:8000 `
  -L 127.0.0.1:17474:127.0.0.1:7474 `
  -L 127.0.0.1:17687:127.0.0.1:7687 root@connect.westc.seetacloud.com
```

工作台为 `http://127.0.0.1:18000/ui/`；Neo4j Browser 为
`http://127.0.0.1:17474/`，其 Bolt 地址填写 `bolt://127.0.0.1:17687`。
SSH 转发断开不会停止服务器服务。不要将 8000、7474 或 7687 开放至公网。

## 从 v0.9.2 切换及回退

切换前检查 v0.9.2 的执行仓库没有正在运行、排队或未结算的请求；记录最新
Revision。维护窗口内先有序停止旧 Web/Neo4j，制作最新 Neo4j dump 和应用
状态备份，生成 SHA-256 清单并验证归档，然后才启动 v0.10。新图谱为空，
旧事实不会出现在新页面。切换失败时停止 v0.10，再用原 v0.9.2 代码、
配置和数据恢复；新库如已写入，先独立备份，绝不覆盖旧库。

旧生产实例的命令必须显式携带原目录配置，不能在旧目录或本目录使用
未核对的默认值执行 `stop`/`start`。v0.10 的 Git 部署不代表发布正式版本。
