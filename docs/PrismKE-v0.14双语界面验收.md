# PrismKE v0.14 双语界面验收记录

## 验收范围

- 分支：`dev/v0.14`
- 软件版本：`0.14.0.dev0`
- 流程协议：`0.13.0`
- 日期：2026-10-27
- 范围：研究工作台中英文切换、通知本地化、浏览器语言状态与响应式开关

本轮只修改展示层和前端测试，不修改 API 契约、Agent 工作流、运行快照、审核记录、图谱模型或生产数据。`dev/v0.14` 完成后不合并 `main`，不创建 `v0.14.0` 标签，也不切换生产服务。

## 实现结果

### 语言模型

- 首次访问固定使用英文，不读取浏览器系统语言。
- 页面右上角提供 `EN / CH` 滑动开关，内部语言代码为 `en` 与 `zh-CN`。
- 切换无需刷新页面，不重新创建运行、不调用模型，也不清空当前表单、文件或运行选择。
- 语言保存在 `localStorage` 的 `prismke.ui.locale.v1` 中；非法值自动回退英文。
- 同一浏览器的标签页通过 `storage` 事件同步；不同浏览器会话的语言互不影响。
- 原始技术 JSON、ID、哈希、文件名、用户输入、API 枚举和数据库字段不翻译。

### 翻译目录

- `frontend/i18n.py` 是应用级唯一翻译源，提供语言归一化、Python 侧翻译和浏览器即时翻译控制器。
- 导航、17 个页面、标签、按钮、帮助文字、占位符、表头、状态、媒体类型、审核决定、空状态和通知均纳入双语目录。
- Gradio 上传、拖放、下载、清除和页脚等内置可见文案同步切换。
- 可见枚举使用本地化显示值，提交到 API 和持久化层的机器值保持不变。
- 静态测试扫描 Gradio 组件中的中文可见字符串；新增文案未登记英文翻译时测试失败。

### 错误与动态消息

- 英文模式通知标题为 `Error`，中文模式为“错误”。
- 已知错误使用经过整理的双语说明；未知异常只显示当前语言的安全概述与错误编号。
- 错误不会覆盖页面结果组件，已有业务数据继续保留。
- 通知使用触发操作时的页面语言；切换语言不会把后端堆栈或原始请求暴露到页面。
- 动态 Markdown、只读结果框及下拉框当前值在内容更新后会重新识别来源文案，不再复用过期翻译缓存。
- 密钥与 Neo4j 配置状态、OCR 自动设备、默认操作者及设置保存结果均支持即时双向切换；展示翻译不触发输入事件，底层枚举和审计值保持不变。
- 英文模式补齐 `No candidate entities available`、`No claims available`、`No decisions available` 等全部动态空状态。

### 开关与响应式

- 桌面开关尺寸为 `112 x 36px`，移动端为 `92 x 32px`。
- 使用浅蓝轨道、白色滑块、品牌蓝文字和琥珀色焦点环，无渐变。
- 支持鼠标、触摸、Tab、Enter 和空格，提供 `role="switch"`、`aria-checked` 与当前操作说明。
- 支持 `prefers-reduced-motion`；通知栈下移，避免与开关重叠。
- 开关根节点及 Gradio 内部包装层均禁止滚动，隐藏标签不占布局，不出现横向或纵向滚动条。
- 页面在初始语言应用完成前保持隐藏，避免首次英文访问出现中文闪烁。

### 比例布局与侧栏

- 桌面端侧栏默认占视口宽度的 `20%`，拖动或键盘可在 `10%–30%` 之间调节，比例保存在浏览器本地。
- 侧栏宽度会在窗口变化时按已保存比例重新计算，不再使用固定像素宽度。
- 桌面端收起侧栏后完全移出视口，主工作区随 `180ms` 过渡扩展为全宽；独立的展开按钮保持可见，可随时恢复侧栏。
- `900px` 及以下视口默认收起侧栏，以抽屉方式覆盖展开，不挤压主工作区。
- 顶部拆分为独立控制带和品牌展示区：桌面控制带约占视口高度 `5%`，语言开关在其中右对齐且垂直居中；品牌展示区约占 `15%`，只承载 Logo、简介和版本。
- 品牌区与主体之间保留约 `1%` 间隔。Logo 同时受品牌区高度和容器宽度约束，按原始比例缩放。
- 移动端使用 `48px` 控制带、`140px` 品牌区和 `8px` 主体间隔，避免直接套用桌面百分比挤压首屏内容。
- 主体内容宽度为当前可用工作区的 `90%`，左右各保留约 `5%` 间距。

### 页面布局细节

- 品牌简介和版本标签均纳入双语切换：英文显示 `An auditable and traceable multimodal knowledge graph construction system.` 与 `Development build`，中文显示“一个可审计、可追溯的多模态知识图谱构建系统。”与“开发版本”。
- 总览“工作区概览”和新建构建“尚未启动构建”只保留 Gradio 外层组件的一条蓝色左边框，内层 Markdown 不再重复绘制边框或背景。
- 执行任务、实体审核、事实审核和视觉审核采用紧凑横向操作栏：字段标签位于下拉框左侧，字段容器约 `64px` 高，刷新按钮作为右侧独立容器与其等高；手机端字段依次堆叠，按钮恢复为 `44px` 全宽。
- 视觉审核的区域证据和审核详情在桌面端等高，移动端上下堆叠；详情展开后内容在自身区域内展示。
- LLM/VLM Base URL 使用可随内容增高的多行输入框，长地址完整换行显示，不产生输入框内部纵向滚动。
- 新建构建的上传操作列与技术详情列底部对齐；技术详情展开后填满右侧剩余高度。
- 新建构建、媒体资产和视觉审核的详情面板采用状态感知布局：收起时只保留不超过 `48px` 的标题栏，内容完全隐藏；展开时再占用剩余高度，不再保留空白或拉高状态摘要。
- 媒体资产和视觉审核统一使用等高证据双栏，右侧 JSON 详情填满面板而非停留在顶部；JSON 的左右边界始终位于 Accordion 内，长内容仅在详情内部纵向滚动。
- Agent 协作轨迹表采用 `10% / 14% / 18% / 17% / 20% / 9% / 12%` 的百分比列宽；宽屏空表和有数据表均铺满容器，小屏仅在表格自身横向滚动。
- 案例库三个筛选项均采用“标签＋下拉框”的横向字段，与“包含已停用”复选框共同位于一个容器；桌面和平板保持同一行，在 `390px` 手机视口改为单列换行。
- 设置保存结果改为自然换行的 Markdown 状态区，不再使用有内部滚动条的只读输入框；中英文结果均可完整展示。

### 抽取结果解释、候选图与导出

- Schema 校验成功后显示绿色 `✓ Valid / ✓ 有效`，并展示 Schema ID、版本、实体类型数、关系数和规范化哈希；切换 Schema 文件、文本或来源时会立即恢复为未校验状态。
- 抽取结果默认按 Canonical Entity ID 聚合；尚未执行实体消歧时，仅按规范化名称和类型形成“同名提及组”，页面明确说明这不是语义合并。
- 原始提及保留 Mention ID、页码、上下文、bbox、Evidence ID、置信度和来源模态，可从聚合结果追溯到每一次出现。
- 运行摘要同时展示任务模式覆盖范围、页数、DocumentIR 文本块、实体、关系、属性、事件、媒体、视觉断言、校验问题和待审核数量。
- 多模态摘要展示请求/实际 PDF 解析器、路由原因、OCR 是否调用及实际设备、VLM 调用次数、媒体类型和证据模态；没有调用 VLM 时明确提示，避免把“文件含图片”误解为“已经完成视觉抽取”。
- 候选关系图只读展示实体、关系、媒体出现、`DEPICTS`、`SUPPORTS` 和视觉断言；点击节点或边会在证据面板显示对应的页码、区域、Evidence ID、哈希和审核信息，不调用 GraphStore，也不产生 Revision。
- 结果导出接口为 `GET /api/v1/runs/{run_id}/export`。默认 ZIP 不含上传原件；只有显式设置 `include_source=true` 才加入经哈希验证的原文件及派生媒体。
- ZIP 固定包含 manifest、结构化结果、Schema 快照、实体/提及/关系/属性/事件/媒体/证据/校验问题 CSV、候选图和证据清单；不包含密钥、密码、绝对路径、原始模型请求或检查点内部字段。

## 自动化验收

- Ruff：通过。
- Mypy：110 个源码文件通过。
- 完整 pytest：共收集 450 项并运行通过，无失败（环境条件项按既有规则跳过）。
- Playwright：30 项通过；默认英文、中文切换、刷新恢复、非法存储回退、标签页同步、会话隔离、键盘操作、错误通知、比例布局、折叠详情、全宽表格、Schema 失效和候选图证据点击均通过。
- 页面覆盖：17 个页面逐页验证英文标题、中文标题和导航可达性。
- 英文完整性：17 个页面的非技术可见文本、输入框当前值和下拉框当前值均未发现未登记中文文案。
- 响应式视口：`2560x1392`、`1440x900`、`820x1180` 与 `390x844` 均无页面级横向溢出；控制带真实占位，语言开关、Logo、侧栏按钮和通知互不遮挡；移动端英文表头保持单行并在表格自身容器内横向滚动。
- 上述四个视口均验证了 Logo 比例缩放、侧栏 `20%` 默认比例、`10%–30%` 调节范围、收起后主体扩展和再次展开。
- 页面细节：状态摘要仅一条蓝色强调边；操作栏字段标签与下拉框中心误差不超过 `3px`，字段容器与刷新按钮高度误差不超过 `2px`；详情收起高度不超过 `48px` 且 JSON 不可见；新建构建展开后左右底边误差不超过 `2px`；媒体资产与视觉审核展开后双栏高度误差不超过 `2px`，JSON 右边界误差不超过 `2px`、底部误差不超过 `12px`；Agent 表头至少覆盖容器宽度的 `99%`；长 Base URL 无内部滚动；案例筛选在 `2560×1392`、`1440×900`、`820×1180` 保持单行并在 `390×844` 正确换行；设置结果没有内部裁切。
- Schema 状态：英文与中文有效摘要均通过浏览器验收；修改 Schema 来源后，绿色有效标识会立即消失，不会沿用失效快照。
- 候选图：浏览器使用真实 Plotly 点击事件选择实体节点，隐藏桥接状态和右侧证据面板同步更新；候选图测试使用独立运行目录，不污染其他页面的空状态验收。
- 聚合语义：未消歧结果按名称和类型分组，消歧结果优先按 Canonical Entity ID 聚合；两种路径均保留原始 Mention 与 Evidence 追踪。
- 导出安全：API 测试验证默认 ZIP 不含原件，显式包含时只导出已校验资产，并扫描敏感配置、服务器绝对路径和内部请求字段。
- 合成真实格式探针：`research-brief.pdf` 解析为 4 页、1 个内嵌媒体资产，自动模式实际选择 PyMuPDF；联合抽取与消歧任务在 Mock Provider 下不创建 Graph Revision。
- 状态保持：切换语言后配置操作者字段和现有 Schema 校验结果保持不变。
- wheel：`prismke-0.14.0.dev0-py3-none-any.whl` 构建成功，在全新虚拟环境中可导入 `src`、`frontend.app` 和 `frontend.i18n`，默认语言为英文。

## 安全与兼容性

- 未调用真实模型、百炼、真实 OCR 或生产 Neo4j。
- 未修改生产 v0.9.2 服务、正式图谱和备份。
- 语言偏好不写入运行快照、数据库、审核记录或 Graph Revision。
- 页面、日志、测试产物和文档不包含 API Key、密码、Base64 图片、完整向量或生产数据。
- v0.13.1 及更早运行保持兼容，工作流协议继续为 `0.13.0`。
