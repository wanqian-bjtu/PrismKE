# PrismKE v0.9.0 评测与验收报告

## 验收范围

本报告验证 v0.9 的审核案例库、BGE-M3 案例检索、受预算约束的 Reflection、API/CLI 页面以及既有 JSON/Neo4j 闭环。真实模型评测不调用 VLM 或 OCR，不连接生产图谱，也不替换当前生产 v0.7 服务。

评测集与此前五份公开材料隔离，包含 6 份开发样例和 12 份最终测试样例，覆盖中英文未知关系、domain/range 错误、错误证据引用、有效候选和不可修复问题。开发集用于实现调试；正式测试集不参与后续 Prompt 调整。

九组配置为：案例模式 `none`、`good`、`good_bad`，分别结合 0、1、2 次 Reflection。真实 Provider 使用服务器现有 `qwen3.7-flash`，案例检索使用本地 BGE-M3。Token 上限为 200,000，达到 180,000 时停止派发新请求。

## 预检问题与修复

首次预检完成了全部矩阵，但 `publish_ready=false`：

| 指标 | 首次结果 |
|---|---:|
| 结构化 JSON 最终成功率 | 100% |
| 案例 Recall@5 | 11.11% |
| 可修复问题修复率 | 66.67% |
| 错误改写率 | 0% |
| 证据保持与可验证率 | 100% |
| 非法 Schema 放行数 | 0 |
| Token | 55,102 |

分析确认了三个通用原因：英文候选查询拼入中文校验说明后被语言检测误分；domain/range 在实体解析前没有形成 Reflection 可见的问题；开发样例不同类别重复使用相同实体，导致相关案例标签区分不足。

修复不包含答案硬编码或降低发布标准：语言检测只读取候选内容，问题代码与说明在判定语言后加入查询；候选阶段直接检查 relation domain/range；各错误类别使用独立实体对，案例摘要加入稳定问题代码。对应回归测试覆盖通用 domain 触发和语言过滤。

## 自动与页面验收

- 案例资格、不可变历史、纠正后停用、投影重放和索引重建均有离线测试。
- 检索按任务、Schema 与语言过滤，运行使用冻结案例快照。
- Reflection 覆盖预算、最多两次、失败回退、证据保持、未知用量阻断和检查点恢复。
- 尝试记录保存模型指纹、响应模型、脱敏请求 ID、Token 与耗时，不保存完整请求或向量。
- 案例库与 Reflection 页面在 `1440x900`、`820x1180` 和 `390x844` 视口通过 Playwright；手机端使用侧栏抽屉，页面级无横向溢出、无脚本错误。
- 页面正文未出现 Authorization、API Key、图片 Base64 或 Embedding 向量。
- Ruff 与 Mypy 通过；完整 pytest 为 299 项通过、14 项按既有条件跳过，专用隔离 Neo4j 测试 102 项通过。

## 结论与边界

正式评测和工程验收满足计划中的全部硬指标，v0.9.0 可以正式发布。该结论只说明当前独立合成文本集上的案例检索和受控修复机制达到工程验收要求，不代表开放域泛化、全文抽取 Precision/F1 或多模态质量。真实审核仍由用户决定，案例不能作为自动批准依据，证据坐标合法也不等于事实语义必然正确。

运行原始结果、请求账本、浏览器截图和详细逐条输出保存在忽略的 `runtime/`，不提交 Git。生产服务升级与 Git 发布分开处理。
