# v0.7 运行管理说明

稳定版本 v0.7.0，软件版本与流程协议均为 0.7.0。正式软件版本不改变已验收的 v0.7 检查点协议。

## 工作区与执行入口

每个运行目录保存 executions.sqlite（执行任务、事件、请求账本和私有响应）、reviews.sqlite（审核事件与投影）以及 LangGraph 检查点。它们不是跨数据库原子事务；恢复时核对真实图提交与检查点。

Web 启动一个异步工作器，同一工作区同时执行一个运行；运行内文本与视觉分支仍并行。CLI run/resume 临时取得工作区所有权并等待结果；Web 已占用时 CLI 不启动第二个工作器，应使用已有 API/页面。execution-status 与 cancel 不需要取得工作器所有权。

```bash
PRISMKE_RUNTIME_DIR=runtime/v07-demo uv run prismke serve --port 8005
PRISMKE_RUNTIME_DIR=runtime/v07-demo uv run prismke execution-status RUN_ID
PRISMKE_RUNTIME_DIR=runtime/v07-demo uv run prismke cancel RUN_ID --operator 研究者 --reason 暂停检查
```

使用独立目录和端口。v0.7 不恢复 v0.6 或更早检查点；旧运行应继续使用对应发布版本。

## 页面与状态

打开“执行任务”，选择运行，可查看执行状态、递增版本、尝试编号、执行轨迹和最后更新时间。取消必须填写操作者与原因，恢复按钮只在服务端允许时可用。页面打开期间每两秒刷新；提交与版本冲突时刷新后再核对。

| 状态 | 含义与动作 |
| --- | --- |
| queued | 持久化排队，可取消；安全任务启动后会执行 |
| running | 正在执行；禁止审核、纠正和提交并发修改 |
| cancelling | 取消已保存，等待在途请求结算，不派发后续请求 |
| cancelled | 已安全停止，不自动恢复；核对后可显式恢复 |
| interrupted | 服务关闭或安全保护暂停；仅通过完整预检的任务可自动恢复 |
| failed | 执行失败，不自动重试；修复原因后显式恢复 |
| awaiting_review | 仍有实体、事实或校验问题待人工处理，不自动批准 |
| awaiting_commit | 等待人工提交确认，不因重启自动写图 |
| completed | 图提交与执行已完成，取消不能撤销已完成事务 |

业务状态保留为原 WorkflowState.status，执行状态独立保存。例如取消后业务摘要可能仍为 running，执行状态已经 cancelled；页面必须依据执行状态判断是否仍在工作。

并行分支的单一“节点”字段表示最后报告进度的分支，不代表另一个分支已结束；执行轨迹保留两者。详细问题列在问题记录中。

## 请求与取消保证

模型请求发送前落盘逻辑编号、输入哈希、Provider 指纹、运行/节点和尝试编号；不保存请求图片 Base64、Authorization 或密钥。收到响应后保存脱敏响应、实际用量及状态，节点重入可复用已保存响应或规范化结果。

取消不直接杀死模型请求；已派发请求等待返回或超时，之后阻止新请求、重试、JSON 修复和下一视觉资产。OCR 在当前资产完成后检查控制信号。图事务开始后不会被用户取消中断；已确认 Revision 落图时结算为 completed，并记录 CANCEL_TOO_LATE_COMMIT_COMPLETED。

缺少用量、超时、连接中断、服务端错误或退出后未结算请求均可能已消费，不算零、不自动重发。只读查询可看到未知请求数量；本版没有人工清除未知账本或强制重发入口。

正常关闭停止接收/执行新任务，最多等待 30 秒；超时保留中断状态与未知请求。重启先恢复审核投影，再核对输入、Schema、策略/Provider 指纹、证据和检查点。失败、取消、正常待审核/待提交与未知请求不自动恢复。中断的确认提交若已落图则幂等结算；未落图要求再次确认。

## API 与错误代码

POST /api/v1/runs 创建/返回已有运行。POST /api/v1/runs/{run_id}/resume 返回 202，表示已排队而非执行已完成；可提交 expected_version。

GET /api/v1/runs/{run_id}/execution 查询执行与允许动作；GET /api/v1/runs/{run_id}/execution-events 查询事件。POST /api/v1/runs/{run_id}/cancel 必须提交 operator、reason、request_id、expected_version。同一 request_id 同内容返回已有取消结果，不重复记账。

| 代码 | 处理方式 |
| --- | --- |
| WORKSPACE_WORKER_BUSY | 使用已有 Web/API，或换独立运行目录 |
| WORKER_SHUTTING_DOWN | 正常关闭期间拒绝新任务，创建接口返回 503 |
| STALE_EXECUTION_VERSION | 返回 409；刷新，重新核对版本 |
| REQUEST_ID_REUSED | 同编号内容不同，拒绝；使用正确原请求或新编号 |
| EXECUTION_BUSY / EXECUTION_NOT_ACTIVE | 任务状态不允许所请求操作 |
| CANCEL_OPERATOR_REASON_REQUIRED | 操作者、原因和请求编号不得空白 |
| AWAITING_REVIEW / SUBMISSION_CONFIRMATION_REQUIRED | 先人工处理，不用恢复替代审核或确认 |
| REVIEW_SYNC_PENDING / PROJECTION_SYNC_PENDING | 投影待恢复，禁止继续修改 |
| UNKNOWN_PROVIDER_REQUEST / UNKNOWN_PROVIDER_USAGE | 先核对服务实际用量与账本，不能自动重发 |
| EXECUTION_INPUT_CHANGED / PROVIDER_CONFIGURATION_CHANGED | 输入或配置与原任务不一致，恢复被阻断 |
| EXECUTION_EVIDENCE_INVALID / CHECKPOINT_MISSING | 证据或检查点不完整，停止自动恢复 |
| LEGACY_EXECUTION_READ_ONLY | 使用对应发布流程，不迁移旧检查点 |

健康接口增加 worker、queued、recovery_blocked，不输出密钥、完整向量或服务器绝对路径。执行中运行变更锁冲突仍沿用审核接口的冲突响应。

## 边界

不引入 Redis/Celery，不实现多用户、优先级或分布式执行。账本结果属于私有运行数据，保留在 Git 忽略目录；不要上传原文、数据库或详细运行结果。

任务队列不代表事实正确，工程验收不能替代真实任务的人工判断。升级部署前应备份运行数据，旧协议运行不得直接迁移到新检查点。
