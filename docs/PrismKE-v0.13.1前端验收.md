## 已实现行为

### 错误通知

- 预期操作错误只使用右上角红色通知，标题统一显示“错误”。
- 已知错误显示具体中文原因，例如“请上传 Schema 文件”和“请填写审核人、原因和请求编号”。
- 未识别异常只显示脱敏后的中文概述和错误编号，完整堆栈仅进入服务器日志。
- 错误发生时返回 `gr.skip()`，保留页面原有输出，不再用页面内 `Error` 组件覆盖图表、JSON、预览或状态区域。
- Gradio 6.27 强制生成的英文通知标题通过页面级 `MutationObserver` 本地化，不改变事件协议和通知正文。

### 中文分类

- 媒体类型在表格和选择器中显示为图片、图表、表格、公式、页面渲染。
- 运行状态、审核状态、决定和视觉对象类型使用统一中文映射。
- 发送到 API、运行快照和技术 JSON 的值仍使用稳定英文枚举。

### 空状态

- 当前运行、媒体出现记录、审核任务、历史记录、校验问题、证据、案例、批次文件和未知请求均有对应中文空状态。
- 无数据时下拉框显示不可选择的提示并禁用；有数据时自动恢复可操作状态。
- 空状态在进入业务服务前归一化为 `None`，不会作为真实 ID 查询或写入审计。

### 基线遗留

以下 3 个测试文件在 `v0.13.0` 基线上仍断言旧的“自动完成”语义，与本轮前端差异无关：

- `tests/test_agents_v010.py`：期望 `completed`，当前视觉审核边界返回 `awaiting_review`。
- `tests/test_evaluation.py`：仍按无需审核的旧流程计算 Claim F1。
- `tests/test_workflow.py`：3 个用例仍期望运行直接完成或立即产生旧式审核列表。

服务器只有 2 GB 内存，整仓 Mypy 和单进程聚合 pytest 会被操作系统终止。因此本轮将 Mypy 按前端模块拆分、pytest 按测试文件拆分，并将每个 Playwright 用例放入独立进程运行。该方式覆盖相同测试内容，同时避免浏览器与类型分析进程累积占用内存。

开发实例的 Neo4j 运行配置使用 256 MB 初始堆、512 MB 最大堆和 256 MB 页缓存，以适配 2 GB cgroup 配额。该调整仅存在于隔离的 `v013` 运行目录，不进入 Git，也不影响生产配置。
